# Release notes

## Unreleased (3.2.0)

- **ASP.NET Core: `OnWebSocketAccepted`.** `EsiurBuilder.OnWebSocketAccepted((context, connection) => …)`
  (`EsiurOptions.WebSocketAccepted`) runs for every accepted WebSocket with its HTTP upgrade request and
  the new `EpConnection`, before admission and before any EP data is read. RPC handlers run in Esiur
  continuations that do not carry the request's async-local state, so this is where a host captures
  request facts such as the host name. An exception rejects the connection.
- **Breaking protocol change: TypeDef cache synchronization.** A client that keeps type
  definitions between connections (a long-lived `Warehouse`, `AutoReconnect`) now validates them
  during connection establishment with the new `SyncTypeDefs` request (0xF): it sends the cached
  `(id, full class name, version, signature)` list and the node answers with the ids that moved,
  the definitions that disappeared and the definitions that changed. Cached definitions are
  updated in place, resources already attached rebind by member name, and the connection starts
  with its type-id map already built. `TypeDefInfo` gains `Signature` (index 0x0A), an
  id-independent hash of the definition. See `docs/typedef-sync.md`.
- Fix: a resource attach no longer resolves its type through a warehouse-wide `(domain, id)`
  key. After the serving node restarted and renumbered its types, that key could point at a
  different type and bind the resource to the wrong definition.
- Generated proxies bind members by name at run time instead of by the index they were generated
  with, so compiled applications keep working when a node renumbers or extends a type. A member
  the node removed throws `EpMemberUnavailableException` naming the member and the type.
  `TypeDefGenerator` output now compiles against the runtime (it referenced a `properties` array
  that no longer exists), casts wire values through `RuntimeCaster` instead of unboxing, and
  resolves static calls by type name.
- Fix: a `TypeDefIdsByNames` request carrying exactly one name was sent as a bare string, failed
  the server cast and was never answered, so a client with a single registered proxy type
  never finished connecting.
- `Warehouse.FindServedTypeDefByName` finds the definitions a node serves (never one it holds as
  a client of another node).

### Migration notes

- Use matching 3.2 runtimes on both ends to benefit from the cache; a client talks to an older
  node as before (a cache sync it does not understand times out after
  `EpConnection.TypeDefSyncTimeout`, default 15 s, and the cache is dropped).
- Regenerate proxies with the 3.2 generator. Proxies generated by older versions keep the old
  literal indexes.

## 3.1.0

- Add generation/revision cursors, resource journals, historical subscriptions,
  and reconnect replay for live properties and events.
- Improve dynamic resource/type definition handling and concurrent attachment
  behavior, with cross-runtime conformance coverage.
- Negotiate and enforce remote parser, allocation, collection, metadata-depth,
  and encrypted-record limits.
- Add opt-in EP connection diagnostics for traffic, queues, and resource state.
- Standardize the default EP port at 51018 when no explicit port is supplied.
- Update the ASP.NET Core adapter and add journal support to EntityCore.
- Release the adapters, stores, and CLI as 3.1.0 with an Esiur 3.1.0 dependency;
  previously published 3.0.x packages are not overwritten.
- Correct the standalone example's endpoint display and exclude nested/stale
  build outputs when building with an external artifacts directory.

### Compatibility and publishing

Use matching 3.1 runtimes when using journals, replay, or negotiated limits.
Keep explicit endpoint ports where an installation does not use port 51018.
Existing .NET target frameworks are unchanged.

Publish `Esiur.3.1.0.nupkg` first, then `Esiur.AspNetCore`,
`Esiur.Stores.EntityCore`, `Esiur.Stores.MongoDB`, and `Esiur.CLI` 3.1.0.
The core security/cryptography project and test/example projects are not
standalone NuGet products.
